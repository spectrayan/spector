Extract key entities and their relationships from the text below.

Rules:
1. Format must be exactly one entry per line. Do not write any introduction, explanation, or code blocks.
2. Entities must use the format: ENTITY: name | TYPE
3. Relationships must use the format: RELATION: source_name | REL_TYPE | target_name
4. The source_name and target_name in RELATION MUST exactly match the names of entities defined in the ENTITY lines.
5. REL_TYPE must be in SCREAMING_SNAKE_CASE (e.g. USES, PART_OF, CAUSED_BY, TRIGGERED).
6. Max %d entities, %d relations.

Preferred entity types (use these when applicable):
PERSON, ORGANIZATION, TEAM, TECHNOLOGY, PROGRAMMING_LANGUAGE, API,
TOOL, DATABASE, SERVICE, PROJECT, PRODUCT, CONCEPT, TOPIC, SKILL, DECISION, EVENT,
LOCATION, DATE_TIME, ARTIFACT, PROCESS, METRIC, ROLE, TASK
You may use other types if none of these fit.

Preferred relationship types (use these when applicable):
CAUSES, CAUSED_BY, LED_TO, RESULTED_FROM, TRIGGERED, TRIGGERED_BY, PREVENTED,
CORRELATED_WITH, ROOT_CAUSE_OF, USES, PART_OF, DEVELOPED_BY, WORKS_ON, MANAGES,
DEPENDS_ON, RUNS_ON, CREATED_BY, LOCATED_IN, MEMBER_OF, IMPLEMENTS, RELATED_TO,
REPORTS_TO, COLLABORATES_WITH, PRECEDES, FOLLOWS, SUPERSEDES
You may use other relationship types if none of these fit.

Example 1:
Input text: "Spector uses the Vector API for SIMD acceleration. It runs on Java 25."
Output:
ENTITY: Spector | PROJECT
ENTITY: Vector API | TECHNOLOGY
ENTITY: Java 25 | TECHNOLOGY
RELATION: Spector | USES | Vector API
RELATION: Spector | RUNS_ON | Java 25
